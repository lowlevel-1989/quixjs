# gfx

English | [Español](README.es.md)

Drawing without JS. The canvas 2d of `binding/canvas/2d/` draws here by
software on an RGBA `Surface` in memory, the same with the sdl backend and
with the dummy one. `gl.c` is the OpenGL ES 2.0 context used by WebGL
(`binding/webgl.c`) and by the sdl backend to present the frame. `gpu2d.c`
draws a 2d canvas on the GPU when a `gpu-canvas` hook asks for it.

| file             | what it does |
|------------------|--------------|
| `surface.h/.c`   | RGBA surface (not premultiplied, same order as ImageData), affine matrix, blending of the `globalCompositeOperation` modes |
| `color.c`        | CSS colors: `#rgb`, `rgb()`, `hsl()`, names...; serialized as the browser does (`#rrggbb` or `rgba(...)`) |
| `paint.c`        | what goes in fillStyle / strokeStyle: color, linear and radial gradient, pattern; sampled per pixel |
| `raster.c`       | paths, fill (nonzero / evenodd), stroke, coverage masks (also for `clip()`), fillRect, clearRect, drawImage |
| `image_loader.c` | decodes images (PNG, JPG...) with SDL_image and saves PNG for the screenshots |
| `font.c`         | TrueType fonts with SDL_ttf: registered families, CSS `font` value, measure and draw text; one thread at a time (the game and the notices over it, drawn by the present thread) |
| `gl.h/.c`        | OpenGL ES 2.0 context for WebGL (hidden SDL window, or offscreen without window); functions loaded with `SDL_GL_GetProcAddress`; a second context that shares textures (`gl_aux_begin` / `gl_aux_end`) for `gpu2d.c` |
| `gl_state.h/.c`  | the OpenGL state of the WebGL context saved and restored: `gpu2d.c` and the screen with libmali (drivers, `one_context`) draw in that context without the game noticing |
| `gpu2d.h/.c`     | 2d canvas drawn on the GPU (hook `gpu-canvas`): fillRect, clearRect, fill and stroke with color or gradient; the rest goes back to the CPU; a full repaint identical to the last one (a light mask with the lights and screen still) is not drawn again; it draws in the WebGL context, saving and restoring its state (`QUIXJS_GPU2D_MAIN=0`: the auxiliary context) |
| `shader_cache.h/.c` | the WebGL programs already linked, kept in `cache/shaders` (next to the toml) (`GL_OES_get_program_binary`): next time they load in a few ms instead of being compiled; if the driver no longer takes one, it is linked and saved again |
| `driver.h/.c`    | which OpenGL ES driver is in use (panfrost, mali or default), read once from `GL_RENDERER` and `GL_VERSION`; the rest of the code asks `gpu_driver()` instead of looking at the name |
| `drivers/*.c`    | one file per driver with what quixjs does differently with it, and why (what was measured) |
| `gl_funcs.h`     | list of the GLES 2.0 functions, generated by `tools/gen_gl.py` (do not edit by hand) |

## No antialiasing

`raster.c` paints a pixel when its center is inside the shape, as with
`imageSmoothingEnabled = false`. Coverage is 0 or 255 per pixel, and the same
mask is used for `clip()`.

## Fast paths

`blend_pixel` (in `surface.h`) handles `source-over` and `lighter` inline with
integers, since almost every draw uses them; the other modes go through
`blend_pixel_slow`. `lighter` over an opaque destination (a light mask of the
lighting plugins of RPG Maker MV) is a capped sum without divisions. `raster_fill_rect` has a
fast path when the matrix only translates and scales, and gradients are
precalculated in a 256 color table (`PaintSampler`).

`raster_light` is the light of the lighting plugins: a fillRect with a
concentric radial gradient in `lighter` mode, without clip or rotation. Its
color comes from a table indexed by the squared distance (no square root),
each row only walks the part inside the circle when the last color adds
nothing, and over an opaque destination it is three capped sums per pixel. A
`lighter` fill with black only touches the pixels that are not opaque.

## GL without GLES on the system

The GL headers are the ones that come with SDL2 and the functions are loaded at
run time, so building does not need GLES installed (not even for PortMaster).
The WebGL context is created on the window of the sdl backend and shares
textures with it: a WebGL canvas is shown without reading it back from the GPU.

## 2d canvas on the GPU

`gpu2d.c` draws the canvases that a `gpu-canvas` hook marks
([hooks](../hooks/README.md)): the light masks of RPG Maker, repainted whole
on every update, are the most expensive drawing by software on a handheld.

- The canvas lives in a texture (premultiplied alpha). It is drawn with a
  second GL context that shares textures with the WebGL one
  (`gl_aux_begin` / `gl_aux_end` in `gl.c`), so it does not touch the GL
  state of the game.
- The drawing commands are queued and drawn at once when needed: when WebGL
  uploads the canvas or when it is read.
- An opaque fill of the whole canvas drops the queued commands (they would not
  be seen) and becomes a `glClear`. A `lighter` fill with black on an opaque
  canvas is skipped.
- On the GPU: fillRect, clearRect, fill and stroke (the coverage of the path
  is computed by software and uploaded as a mask), with a color or a gradient
  (linear, or radial with one center), globalAlpha, the transform and the
  modes source-over, lighter, destination-out, destination-over, source-atop,
  xor and screen.
- One shader program per paint (color, linear, radial) and with or without
  mask: no branches in the fragment shader. The shaders are in
  [shaders](../shaders/README.md).
- Anything else (clip, patterns, other modes, text, images, getImageData...)
  reads the canvas back and the canvas stays on the CPU.
- `texImage2D` of WebGL with that canvas copies it on the GPU with
  `glCopyTexSubImage2D` (`glCopyTexImage2D` the first time or when the size
  changes), when the game asks for premultiplied alpha and no flip, as PIXI
  does. Otherwise it is read like any canvas.
- `drawImage` of that canvas reads it, and the canvas stays on the GPU.

## Fonts

A family is registered from JS (FontFace, `@font-face`) or from `[fonts]` in
the toml of the game. If a family is not registered, the default font is used: the
`QUIXJS_FONT` environment variable or the first one found from a list of usual
Linux fonts (DejaVu, Noto, Liberation).
